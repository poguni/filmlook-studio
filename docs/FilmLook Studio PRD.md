## 1. 개요

### 1.1 한 줄 정의

사진 한 장에 필름 시뮬레이션풍 프리셋 7종을 입혀 보고, 8칸 ‘밀착 인화’에서 마음에 드는 컷을 골라 강도를 조절한 뒤 JPEG로 저장하는 브라우저 기반 사진 편집기입니다. 같은 기능을 세 가지 테마(암실, 카메라 기어, 파스텔 사진관)로 바꿔 입을 수 있습니다.

### 1.2 배경

- 후지필름의 필름 시뮬레이션은 카메라 내부에서 RAW 데이터에 적용되므로, 후지 카메라가 없으면 같은 색감을 얻기 어렵습니다.
- Lightroom, Capture One의 후지 프로필은 **후지 RAW(RAF) 파일에만** 적용됩니다. 갤럭시 스마트폰이나 소니 카메라의 JPEG에는 쓸 수 없습니다.
- 범용 필터 앱(VSCO 등)은 여러 필름 룩을 제공하지만, 같은 사진에 여러 룩을 한꺼번에 깔아 놓고 비교하는 경험은 부족합니다.

### 1.3 목표

| 구분 | 목표 |
|---|---|
| 사용 목표 | 갤럭시·소니 JPEG에 후지 감성 색감을 빠르게 입히고, 원본 해상도로 저장한다. |
| 경험 목표 | 3번의 동작(사진 열기 → 컷 고르기 → 저장) 안에 결과물을 얻는다. |
| 포트폴리오 목표 | WebGL2 셰이더, 3D LUT 색 처리, 반응형 UI를 보여 주는 완성도 있는 공개 프로젝트로 만든다. |

### 1.4 비목표 (하지 않는 것)

- RAW, HEIC, PNG, WebP 등 JPEG 이외 형식 지원
- 여러 장 일괄 처리, 부분 보정(브러시, 마스크), 자르기·회전 등 일반 편집 기능
- 회원 가입, 서버 업로드, 클라우드 저장
- iOS·Android 네이티브 앱
- 후지필름 카메라 내부 결과와의 픽셀 단위 일치

- **주 사용자:** 본인 1명 (갤럭시 스마트폰, 소니 미러리스 사용자)
- **부 사용자:** 포트폴리오 방문자 (데모로 앱을 체험하는 사람)

|---|---|---|

| 소니 미러리스 | 24~33MP (a7 IV 등), 최대 61MP (a7R V 등) | 색공간을 Adobe RGB로 설정했을 수 있음, EXIF 회전 정보 사용 |

## 3. 핵심 사용자 흐름

```
[사진 열기] → [한 화면: 밀착 인화 8칸 + 미리보기 + 조절판] → [JPEG 저장]
                  └─ 칸 누르기 → 미리보기에 즉시 적용 → 비교·강도 조절 ─┘
```

v1.3부터 밀착 인화와 편집 화면을 **한 화면으로 합쳤습니다**(디자인 시안 기준). 화면 전환 없이 고르고, 비교하고, 저장합니다.

1. 사용자가 사진을 드래그 앤 드롭하거나 파일 선택 버튼으로 엽니다.
2. 데스크톱에서는 왼쪽 열(B 테마는 화면 아래 필름 스트립), 스마트폰에서는 미리보기 아래 가로 스크롤 줄에 원본 1칸과 프리셋 7칸이 나타납니다. 사용자 LUT를 불러왔다면 9번째 칸이 더해집니다.
3. 칸을 누르면 가운데 미리보기에 바로 적용됩니다. 처음에는 사진 전체가 결과로 보입니다.
4. 사진 위를 좌우로 끌어 원본과 결과를 비교하고, 강도·입자·흑백 필터를 조절합니다.
5. 저장 버튼을 누르면 원본 해상도 JPEG가 만들어져 저장됩니다. 스마트폰에서는 이어서 ‘공유’ 버튼으로 공유 시트를 열 수 있습니다(S-04).

## 4. 기능 요구 사항

우선순위: **P0** = MVP 필수, **P1** = 1차 완성(2주 차) 포함, **P2** = 이후 확장

### 4.1 사진 불러오기

| ID | 요구 사항 | 우선순위 |
|---|---|---|
| F-01 | 파일 선택 버튼과 드래그 앤 드롭으로 JPEG 1장을 연다. | P0 |
| F-02 | EXIF 회전 정보를 반영해 올바른 방향으로 표시한다. | P0 |
| F-03 | JPEG가 아닌 파일은 거부하고 안내 메시지를 보여 준다. | P0 |
| F-04 | 64MP를 넘는 사진(예: 갤럭시 200MP)은 “64MP로 줄여서 편집” 선택지를 제공한다. 전체를 디코딩하기 전에 JPEG 헤더(SOF)에서 크기를 먼저 읽어 판단한다. | P2 (v1.8: 쓰는 사진이 24MP 이하라 필요해질 때 만듦) |
| F-05 | ICC 프로필이 Adobe RGB인 경우 sRGB로 변환하거나, 최소한 경고를 표시한다. **M1 확인 결과:** Chromium은 `createImageBitmap` 디코딩 단계에서 ICC 프로필을 sRGB로 자동 변환한다(Adobe RGB 프로필을 넣은 테스트 JPEG로 확인, e2e 테스트로 고정). 따라서 앱은 따로 변환하지 않고 “sRGB로 변환해 편집합니다” 안내만 표시한다. 실제 소니 Adobe RGB 사진과 삼성 인터넷에서의 확인은 남아 있다. | P1 |
| F-06 | 사진이 없을 때 체험용 샘플 사진 3장(본인 촬영, 저장소에 포함)을 제공한다. 샘플은 `npm run samples -- 사진…`으로 EXIF·GPS를 지운 사본을 `public/samples/`에 넣고, 앱은 `public/samples/index.json` 목록이 비어 있지 않을 때만 샘플 버튼을 보여 준다(v1.8). | P1 |

### 4.2 프리셋

| ID | 요구 사항 | 우선순위 |
|---|---|---|
| P-01 | 모든 프리셋은 내부적으로 33×33×33 3D LUT 하나로 처리한다. | P0 |
| P-02 | 프리셋은 JSON 파라미터(톤 커브, HSL, 채도, 화이트밸런스, 스플릿 토닝, 흑백 혼합)로 정의하고, 실행 시 LUT로 “굽는다”. 처리 순서·단위·색공간은 5.4 색 처리 명세를 따른다. | P0 |
| P-03 | MVP에서는 ‘비비드 슬라이드’(벨비아풍), ‘다큐 크롬’(클래식 크롬풍) 2종을 제공한다. | P0 |
| P-04 | 1차 완성에서는 7종 전체를 제공한다(5장 참고). | P1 |
| P-05 | 외부 .cube 파일을 불러와 사용자 프리셋으로 쓸 수 있다. 불러온 LUT는 밀착 인화의 9번째 칸(코드 `U01`, 이름은 파일 이름)으로 붙는다. 한 번에 1개만 두고, 새로 불러오면 바꿔 끼운다. 불러온 파일은 브라우저 안에만 머문다. | P1 |
| P-06 | 외부 LUT의 입력 감마를 ‘sRGB’ 또는 ‘F-Log2’ 중에서 선택할 수 있다(6.4 참고). | P2 |

### 4.3 밀착 인화

| ID | 요구 사항 | 우선순위 |
|---|---|---|
| C-01 | 원본 1칸과 프리셋 7칸, 총 8칸을 미리보기와 같은 화면에 항상 보여 준다(데스크톱 왼쪽 2열 격자, B 테마는 아래 필름 스트립, 스마트폰 가로 스크롤 줄). 사용자 LUT(P-05)를 불러오면 9번째 칸이 더해진다. | P1 (MVP는 원본+2칸) |
| C-02 | 각 칸에 프레임 번호와 프리셋 이름을 표시하고, 선택 표시는 테마별 방식(그리스 펜슬 동그라미 / LOADED 표시 / 하트 도장)을 따른다. | P1 |
| C-03 | 칸을 누르면 화면 전환 없이 해당 프리셋이 미리보기에 바로 적용된다. | P0 |
| C-04 | 칸을 길게 누르거나(스마트폰) 마우스를 올리면(데스크톱) 확대 미리보기를 보여 준다. | P2 |
| C-05 | 마음에 드는 칸에 별표를 표시해 후보를 좁힐 수 있다. | P2 |

### 4.4 미리보기와 조절

| ID | 요구 사항 | 우선순위 |
|---|---|---|
| E-01 | 좌우 비교 슬라이더: 사진 위 어디든 끌면 경계선이 따라오며, 왼쪽은 원본, 오른쪽은 결과를 보여 준다. 키보드 `←`/`→`로도 움직인다. 기본 위치는 0%(경계선이 왼쪽 끝, 사진 전체가 결과)이며, 사진을 새로 열어도 0%로 돌아간다. | P0 |
| E-02 | 강도 슬라이더: 0~100%, 기본값 100%. `결과 = mix(원본, 프리셋, 강도)`로 계산한다. 강도 0%이면 입자도 넣지 않아 결과가 원본과 같다. | P0 |
| E-03 | 프리셋 바꾸기: 밀착 인화(C-01)가 같은 화면에 있으므로 별도 썸네일 줄을 두지 않는다. | P0 |
| E-04 | 원본 보기: 버튼을 누르고 있는 동안 원본을 보여 준다. 키보드는 버튼에서 Space·Enter를 누르고 있거나 `\`를 누르고 있는 동안(v1.8). | P1 |
| E-05 | 그레인: 양(0~100)과 크기(작게/크게)를 조절한다. 저장 해상도에 맞춰 크기를 보정한다. 프리셋을 고를 때마다 양은 그 프리셋의 `defaultGrain`으로 바뀐다(M07은 25, 나머지는 0, 원본과 사용자 LUT는 0). 직접 조절한 값은 이때 덮어쓴다. **크기 보정(v1.7):** 입자 한 칸은 ‘작게’ 1, ‘크게’ 2.2에 사진 긴 변 ÷ 2048(1보다 작으면 1)을 곱한 원본 픽셀 크기로 정한다. 따라서 미리보기(긴 변 2048px)와 원본 해상도 저장 결과에서 사진 대비 같은 크기로 보인다. | P1 |
| E-06 | 비네팅: 양(0~100)을 조절한다. | P2 |
| E-07 | 확대 보기: 100% 크기로 확대해 디테일을 확인한다(데스크톱 휠, 스마트폰 두 손가락). | P2 |
| E-08 | 흑백 필터 옵션: ‘모노 그레인’(M07)을 선택하면 필터 선택(없음·노랑·빨강·초록)이 나타난다. 필터는 별도 프리셋이 아니라 M07의 옵션이며, 밀착 인화에는 ‘없음’으로 표시한다. | P1 |

### 4.5 저장

| ID | 요구 사항 | 우선순위 |
|---|---|---|
| S-01 | 원본 해상도 그대로 JPEG로 저장한다. 기본 품질은 92%. 단, 스마트폰은 6.3의 해상도 상한을 넘으면 안내한 뒤 상한 크기로 줄여 저장한다. | P0 |
| S-02 | 파일 이름은 `원본이름_프리셋코드.jpg` 형식으로 만든다(예: `DSC01234_V02.jpg`). | P0 |
| S-03 | 원본의 EXIF(촬영 날짜, 카메라, 렌즈, 노출 정보, **GPS 위치 정보**)를 결과 파일에 그대로 보존하고, 회전 정보만 ‘정방향’으로 초기화한다. 세부 처리는 6.3 ‘EXIF 처리’를 따른다. (v1.7 구현: `src/io/exif.ts`) | P1 |
| S-04 | 스마트폰에서는 Web Share API로 공유 시트를 띄워 갤러리 저장이나 메신저 전송을 쉽게 한다. 공유 시트는 사용자가 방금 누른 동작에서만 열리므로, 저장(렌더링)이 끝나면 버튼이 ‘공유’로 바뀌고 한 번 더 눌러 연다(두 단계). 지원하지 않으면 일반 다운로드로 대체한다. 스마트폰 판별은 6.3 상한과 같은 방식이며, 데스크톱 Chrome이 파일 공유를 지원해도 데스크톱은 바로 내려받는다(v1.8). | P1 |
| S-05 | 저장 품질을 80/92/100% 중에서 고를 수 있다. | P2 |
| S-06 | 저장 중에는 진행 표시를 보여 주고, 다른 조작을 막는다. | P0 |

### 5.4 색 처리 명세 (LUT 굽기)

LUT를 구울 때 33³ 격자점마다 아래 순서로 계산합니다. CPU에서 한 번만 계산하므로(약 3.6만 점) 속도보다 정확도를 우선합니다. 아래 단위와 범위는 **초기 정의**이며, 튜닝 중 바꾸면 이 표와 단위 테스트를 함께 고칩니다.

| 순서 | 단계 | 파라미터와 범위 | 계산 공간 | 정의 |
|---|---|---|---|---|
| 0 | 입력 | — | sRGB(감마) 0~1 | LUT 입력 좌표 = sRGB로 인코딩된 RGB |
| 1 | 화이트밸런스 | `whiteBalance.temp`, `tint`: −100~100 | 선형광 | temp는 파랑↔주황 축, tint는 초록↔마젠타 축의 채널 배율. 휘도는 유지 |
| 2 | 흑백 혼합 | `mono.mix` (R·G·B 합 1) | 선형광 | M07만 적용. `Y = r·R + g·G + b·B`로 회색을 만든 뒤 이후 단계를 거침. 필터(E-08)는 `mix` 값을 바꿔 끼움 |
| 3 | 대비 | `contrast`: −100~100 | sRGB(감마) | 중간 회색 0.5를 기준으로 한 S자 곡선. 양수면 대비 증가 |
| 4 | 블랙 | `black`: −100~100 | sRGB(감마) | 양수면 가장 어두운 값이 들림(섀도 띄우기), 음수면 블랙이 눌림 |
| 5 | 톤 커브 | `toneCurve`: 0~1 점 목록 | sRGB(감마) | 단조 3차 보간(Fritsch–Carlson). R·G·B에 똑같이 적용 |
| 6 | 구간별 HSL | `hsl.<구간>.hue`: −30~30(°), `sat`·`lum`: −100~100 | OKLCh | 각 구간의 중심은 대표 sRGB 색(빨강 `#ff0000` 등)의 OKLCh 색상각. 이웃 구간과 부드럽게 겹치는 가중치로 섞음 |
| 7 | 전체 채도 | `saturation`: −100~100 | OKLCh | 채도(C)를 `1 + saturation/100`배 |
| 8 | 스플릿 토닝 | `splitTone.shadows/highlights.hue`: 0~360(OKLCh 색상각 °), `sat`: 0~100(%) | OKLab | 명도(L)에 따른 부드러운 가중치로 섀도와 하이라이트에 각각 색을 더함 |
| 9 | 출력 | — | sRGB(감마) 0~1 | sRGB 범위를 벗어나면 색상각과 명도를 유지한 채 채도를 줄여 안으로 넣음(단순 자르기 금지) |

- 흑백 혼합(2단계)을 대비·톤 커브보다 앞에 둔 이유: 필터 효과(하늘이 어두워짐 등)는 채널 혼합에서 생기고, S자 커브는 흑백으로 바뀐 사진에 걸려야 의도대로 보이기 때문입니다.
- 1단위가 움직이는 양(코드의 `SCALE`, `src/color/pipeline.ts`): temp 100 → 빨강 ×1.25·파랑 ×0.75(휘도 보정 전), tint 100 → 초록 ×0.8, contrast 100 → 중간 회색 기울기 2배, black 100 → 블랙 0.25까지 들림, 구간 lum 100 → OKLab 명도 +0.2, 스플릿 sat 100% → OKLab 채도 0.1. 구간 색상·명도 조절은 OKLCh 채도 0.04 미만에서 점점 약해져 회색은 회색으로 남습니다.
- 셰이더는 LUT 조회(하드웨어 삼선형 보간), `mix(원본, LUT 결과, 강도)`, 그레인만 맡습니다. 프리셋별 분기는 넣지 않습니다.
- **그레인(v1.7):** 사진 픽셀 좌표(타일이면 타일 위치를 더한 좌표)의 정수 해시로 만든 값 노이즈(−1~1)를 R·G·B에 똑같이 더합니다. 진폭은 `입자 양/100 × 0.12`이고, 중간 톤에서 가장 크도록 `0.35 + 2.6·L·(1−L)`(L은 sRGB 휘도)을 곱합니다. 강도 0%면 넣지 않습니다. 같은 좌표에서는 타일 크기와 상관없이 같은 값이 나오므로 이음매가 생기지 않습니다(e2e로 확인).
- LUT는 `RGBA16F` 3D 텍스처로 올립니다. WebGL2에서 선형 보간이 보장되는 실수 형식이기 때문입니다(`RGBA32F`는 확장이 필요해 모바일에서 보장되지 않음).
- `mix`와 그레인은 sRGB(감마) 값에서 계산합니다.
- M07의 흑백 필터 4종은 LUT를 따로 구워 캐시합니다. 사용자 LUT(`U01`)는 위 단계를 거치지 않고 .cube 값을 그대로 씁니다.
- 단위 테스트: ① 모든 파라미터가 0이면 LUT가 항등(채널별 오차 0.5/255 이내), ② 강도 0%면 결과가 원본과 채널별 ±1 이내(9장 ‘색 정확도’), ③ 각 단계가 정해진 방향으로 움직이는지(예: `contrast` 양수면 0.25 지점이 어두워짐).

### 6.2 처리 파이프라인

```
JPEG 파일
  → createImageBitmap(imageOrientation: 'from-image')   // 회전 반영 디코딩
  → (Adobe RGB면 sRGB 변환)
  → WebGL2 텍스처 업로드
  → 프래그먼트 셰이더:
       1) 원본 색 읽기
       2) 3D LUT 조회 (하드웨어 삼선형 보간)
       3) mix(원본, LUT 결과, 강도)
       4) 그레인·비네팅 추가 (강도 0%면 생략)
       5) 비교 슬라이더 위치에 따라 원본/결과 선택 (미리보기 전용)
  → 화면 표시 / 저장용 렌더 타깃
```

- **프리셋 → LUT 굽기:** JSON 파라미터를 CPU에서 33³ 격자점에 적용해 LUT를 만들고(5.4), 프리셋별로 메모리에 캐시합니다.
- **미리보기:** 화면 크기에 맞춘 축소본(긴 변 최대 2048px)으로 실시간 처리합니다.
- **밀착 인화:** 긴 변 512px 축소본 1장을 8번 렌더링합니다.

### 6.3 고해상도 저장

| 항목 | 방침 |
|---|---|
| 처리 방식 | 원본을 2048×2048 타일로 나눠 렌더링하고, 결과를 하나의 캔버스에 이어 붙인 뒤 JPEG로 인코딩 |
| 그레인 일관성 | 그레인 노이즈는 타일 좌표가 아닌 원본 픽셀 좌표 기준으로 생성해 이음매가 생기지 않게 함 |
| 최대 크기 | 64MP (소니 61MP, 갤럭시 50MP 포함). 초과 시 F-04에 따라 축소 |
| 스마트폰 상한 | 타일로 렌더링해도 결과는 캔버스 하나에 모아 인코딩하므로 61MP면 약 244MB(RGBA)가 필요합니다. M3에서 갤럭시 실기기로 24·50·61MP 저장을 측정해 안정적으로 저장되는 상한을 정하고, 그 값을 이 표에 적습니다. 상한을 넘는 사진은 안내한 뒤 상한 크기로 줄여 저장합니다. 데스크톱은 원본 해상도를 유지합니다. **v1.8 결정: 상한 24MP.** 실제로 쓰는 갤럭시·소니 사진이 24MP 이하라 실기기 측정 없이 이 값으로 정했습니다(`PHONE_LIMIT_MP`, `src/io/limits.ts`). 스마트폰 판별은 `navigator.userAgentData.mobile`, 없으면 사용자 에이전트로 합니다. 나중에 고화소 사진을 쓰게 되면 아래 방법으로 측정해 고칩니다. 측정 방법: PC에서 `npm run dev -- --host`로 띄운 뒤 갤럭시에서 `주소?cap=0`(상한 없음)으로 열어 24·50·61MP 사진을 저장하면, 개발 서버에서만 저장 시간과 크기가 안내 줄에 표시됩니다. `?cap=50`처럼 상한을 바꿔 볼 수도 있습니다 |
| 실행 위치 | 가능하면 Web Worker + OffscreenCanvas로 UI 멈춤 방지 |
| 갤럭시 Ultra HDR | 게인 맵은 버리고 일반(SDR) JPEG로 저장. 이 사실을 앱 정보 화면에 안내 |

**EXIF 처리 (S-03)**

`canvas.toBlob`으로 만든 JPEG에는 EXIF가 없으므로, 원본의 EXIF를 다시 끼워 넣습니다.

1. 원본에서 EXIF가 담긴 APP1 영역만 가져옵니다. MPF·게인 맵 등 APP2 영역(Ultra HDR)과 XMP는 옮기지 않습니다.
2. 회전 정보(Orientation)를 1(정방향)로 바꾸고, 가로·세로 크기 태그(PixelXDimension, PixelYDimension)를 결과 크기로 고칩니다.
3. EXIF 안의 작은 썸네일(IFD1)은 보정 전 모습이라 갤러리가 보정 전 사진을 보여 줄 수 있으므로 지웁니다.
4. 결과 JPEG의 SOI 바로 뒤에 고친 APP1을 넣습니다. 결과는 sRGB이므로 원본의 ICC 프로필(Adobe RGB 등)은 옮기지 않습니다.

piexifjs는 2018년 이후 관리되지 않으므로, 위 작업만 하는 작은 모듈을 `src/io/`에 직접 작성하는 방안을 먼저 검토합니다.

### 6.4 외부 LUT와 F-Log2 모드 (P1~P2)

- 사용자는 .cube 파일(17³·33³·65³)을 불러올 수 있습니다. 파일은 브라우저 메모리에만 있고 서버로 전송되지 않습니다.
- **F-Log2 입력 모드:** 후지필름이 공개한 F-Log2 → 필름 시뮬레이션 LUT는 F-Log2 영상을 입력으로 가정합니다. 이 모드는 sRGB → 선형광 → F-Log2 인코딩을 거친 뒤 LUT를 적용합니다. F-Log2 수식은 후지필름 공식 데이터 시트의 값을 사용합니다.
- **저장소 정책:** 후지필름 공식 LUT는 재배포 조건이 확인되지 않았으므로 **저장소에 포함하지 않습니다.** 로컬 테스트용 폴더(`luts/private/`)는 `.gitignore`에 등록합니다.
- 결과는 RAW가 아닌 JPEG를 다시 가공한 근사치임을 화면에 안내합니다.

## 7. 프리셋 튜닝 방법 (후지 카메라 없이)

1. **개발용 튜닝 화면(`/tuning`)을 만듭니다.** 모든 JSON 파라미터를 슬라이더로 조절하고, 결과 JSON을 복사할 수 있습니다. (v1.7 구현: 개발 서버의 `/filmlook-studio/tuning`에서만 열리며 배포 빌드에는 들어가지 않습니다. 기준 프리셋을 불러와 고친 뒤 ‘JSON 복사’로 `src/presets/<코드>.json`에 붙여 넣습니다.)
2. **참고 이미지를 준비합니다.**
   - 후지필름 공식 사이트의 필름 시뮬레이션 소개 페이지와 예시 사진
   - 필름 시뮬레이션 레시피 커뮤니티의 예시 사진
3. **(선택) 공식 LUT를 로컬 참고용으로 씁니다.** 후지필름 공식 F-Log2 LUT를 `luts/private/`에 두고 F-Log2 모드로 적용한 결과를 레퍼런스로 삼아, 자체 프리셋을 분할 화면으로 비교하며 맞춥니다. 공식 LUT 자체는 배포하지 않습니다.
4. **검증용 사진 세트로 확인합니다.** 갤럭시·소니로 찍은 하늘·초록 풍경, 인물 피부, 실내 조명, 야경, 회색·흰색 물체 사진 10장으로 모든 프리셋을 점검합니다.
5. **점검 기준:** 피부가 탁해지지 않는지, 하늘에 계단 현상(밴딩)이 없는지, 하이라이트가 하얗게 날아가지 않는지, 회색이 회색으로 남는지(흑백·의도적 색조 제외) 확인합니다.

## 8. 화면 설계 (반응형)

세부 디자인(토큰, 컴포넌트, 테마별 장식, 문구)은 **`design/DESIGN.md`**, 실제 모습은 **`design/mockups/`**의 HTML 시안을 기준으로 합니다. 이 장에는 배치 원칙만 적습니다.

### 8.1 데스크톱 (1440×900, 16:10, 화면 폭 전체 사용)

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 헤더: 로고 · (테마 기믹 토글) · [테마] · [사진 열기] · [저장]             │
├───────────────┬──────────────────────────────────────┬───────────────────┤
│ 밀착 인화     │ 미리보기 (3:2, 가운데 열 전체 폭)     │ 조절판            │
│ 2열 × 4행     │ 사진 위를 끌어 원본/결과 비교         │ · 강도            │
│ 300~340px     │ 아래: 현재 프리셋 이름·부제           │ · 입자            │
│               │                                      │ · 흑백 필터(M07)  │
│               │                                      │ · 저장 정보·버튼  │
│               │                                      │ 300~360px         │
└───────────────┴──────────────────────────────────────┴───────────────────┘
```

- 가운데 열이 남는 폭을 모두 차지합니다(1440px에서 약 640~700px, 더 넓은 화면에서는 계속 늘어남).
- B 테마는 밀착 인화를 왼쪽 열 대신 **화면 아래 전체 폭 필름 스트립**(8칸 1줄, 사용자 LUT가 있으면 9칸)으로 배치하고, 왼쪽 열에는 카메라 일러스트와 장전된 필름 정보를 둡니다. 1440×900에서 페이지 스크롤 없이 헤더·뷰파인더·LCD 줄·필름 스트립이 모두 보이도록 미리보기 높이를 제한합니다(`design/DESIGN.md` 3.2).
- 키보드 단축키: `1` 원본, `2`~`8` 프리셋 P01~M07, `9` 사용자 LUT(있을 때), `\` 원본 보기(누르고 있는 동안), `Ctrl+S` 저장, `←`/`→` 비교 슬라이더 이동, `T` 테마 바꾸기(M5부터)
- 포커스가 슬라이더·입력 칸에 있으면 그 요소가 키를 먼저 씁니다. 예를 들어 강도 슬라이더에 포커스가 있을 때 `←`/`→`는 강도를 바꾸고, 숫자·`T`·`\` 단축키는 동작하지 않습니다. `Ctrl+S`는 언제나 동작합니다.

- 미리보기와 조절판 2열, 밀착 인화는 미리보기 아래 가로 스크롤 줄로 옮깁니다.

## 9. 비기능 요구 사항

| 구분 | 기준 |
|---|---|
| 미리보기 반응 속도 | 슬라이더 조작 후 화면 갱신 50ms 이하 (데스크톱), 100ms 이하 (갤럭시 중급 기종) |
| 밀착 인화 생성 | 사진을 연 뒤 8칸 표시까지 1초 이하 |
| 저장 시간 | 24MP 기준 데스크톱 3초, 스마트폰 8초 이하 / 61MP 기준 데스크톱 8초, 스마트폰 20초 이하 (스마트폰 61MP는 6.3 상한 안일 때만 해당). **M2 측정:** 24MP(6000×4000), V02, 데스크톱 Chrome에서 약 0.6초. 스마트폰은 아직 측정하지 않음. **M3 측정:** 61MP(9504×6336) 합성 사진, N05, 헤드리스 Chromium(소프트웨어 GPU)에서 약 2.7초, 결과 크기 확인(e2e `large.spec.ts`). 실제 카메라 사진은 디코딩이 더 오래 걸릴 수 있어 확인이 남아 있음 |
| 메모리 | 데스크톱은 61MP 처리 중 탭이 강제 종료되지 않을 것 (타일 처리로 확보). 스마트폰은 6.3에서 정한 상한 안에서 강제 종료되지 않을 것 |
| 개인 정보 | 사진은 기기 밖으로 나가지 않음. 외부 분석 도구나 서버 업로드 없음 |
| 색 정확도 | 강도 0%의 렌더 결과가 원본과 채널별 ±1 이내. JPEG 인코딩 자체의 손실을 빼기 위해 **인코딩 전 렌더 결과**(`readPixels`)로 비교한다 |
| 접근성 | 모든 조작을 키보드로 가능, 슬라이더에 값 읽기 지원(aria), 세 테마 모두 글자 대비 4.5:1 이상, `prefers-reduced-motion` 존중 |
| 호환성 | WebGL2 미지원 브라우저에서는 안내 메시지 표시 |
