색감 사진관 (FilmLook Studio) 개발 보고서 (v1)

작성일: 2026-11-25버전: v1

1. 개요

항목내용
앱 이름색감 사진관 (FilmLook Studio), 저장소 filmlook-studio
한 줄 소개JPEG 사진 한 장에 필름 시뮬레이션풍 프리셋 7종을 입혀 보고, 밀착 인화 8칸에서 골라 강도를 맞춘 뒤 원본 해상도 JPEG로 저장하는 브라우저 앱(PWA)
대상 사용자주 사용자는 본인(갤럭시 스마트폰·소니 미러리스 사용자), 부 사용자는 포트폴리오 방문자
화면 기준데스크톱 1440×900, 스마트폰 360~430px
테마A 암실, B 카메라 기어(기본), C 파스텔 사진관. 기능은 같고 겉모습만 다름
개발 기간기획 문서 정리 후 M1~M5와 P2 확장까지 커밋 12개 (모두 2026-11-25에 커밋)
규모소스(src) 약 9,300줄, 단위 테스트 83개, 화면(e2e) 테스트 35개

2. 목표 및 배경

후지필름의 필름 시뮬레이션은 카메라 안에서 RAW에 적용되고, Lightroom·Capture One의 후지 프로필도 후지 RAW 파일에만 쓸 수 있습니다. 그래서 갤럭시·소니 JPEG에는 같은 감성을 입히기 어렵습니다. 범용 필터 앱은 룩이 많지만 같은 사진에 여러 룩을 한꺼번에 깔아 놓고 비교하기는 불편합니다.

구분목표
사용 목표갤럭시·소니 JPEG에 후지 감성 색감을 빠르게 입히고 원본 해상도로 저장
경험 목표사진 열기 → 컷 고르기 → 저장, 세 번의 동작으로 결과물 얻기
포트폴리오 목표WebGL2 셰이더, 3D LUT 색 처리, 반응형 UI를 보여 주는 공개 프로젝트

하지 않기로 한 것: RAW·HEIC 등 JPEG 외 형식, 여러 장 일괄 처리, 부분 보정·자르기, 회원 가입·서버 업로드, 네이티브 앱, 후지 카메라 결과와의 픽셀 단위 일치.

3. 주요 기능

3.1 편집

  • 원본 1칸과 프리셋 7칸(P01 데일리, V02 비비드 슬라이드, A03 소프트 포트레이트, C04 다큐 크롬, N05 네거 스냅, E06 시네마 소프트, M07 모노 그레인)을 밀착 인화로 한 화면에 보여 줌
  • 사진 위 어디든 끌어 원본과 결과를 나눠 보는 비교 슬라이더(마우스·터치·방향키), 누르고 있는 동안 원본 보기
  • 강도(0~100%), 입자(양·크기), 비네팅, M07 전용 흑백 필터(노랑·빨강·초록)
  • 외부 .cube LUT를 9번째 칸으로 불러오기
  • 별표로 후보 표시, 100% 확대 보기(원본 해상도 1:1, 끌기·방향키 이동)

3.2 저장

  • 2048px 타일 렌더링으로 원본 해상도 저장(61MP 확인), 파일 이름 원본이름_프리셋코드.jpg
  • 저장 품질 80/92/100% 선택
  • EXIF(GPS 포함) 보존, 회전 정보만 정방향으로, EXIF 썸네일·Ultra HDR 게인 맵·ICC 제외
  • 스마트폰은 24MP 상한을 넘으면 줄여 저장하고, 공유 시트를 여는 두 단계 공유

3.3 그 밖의 기능

  • 테마 3종과 테마 전환 메뉴·단축키 T, 테마별 기믹(작업등, 뷰파인더 격자선, 반짝이)
  • 마지막 테마와 편집 값(프리셋·강도·입자·흑백 필터·비네팅·품질) 기억
  • PWA 설치와 오프라인 실행
  • 키보드 단축키, 앱 정보(비제휴 고지·개인 정보 안내) 화면

4.1 폴더 구조

폴더하는 일
src/color/sRGB ↔ 선형광 ↔ OKLab/OKLCh, 단조 3차 톤 커브, HSL 8구간, LUT 굽기, .cube 파서
src/gl/WebGL2 렌더러, LUT·입자·비네팅 셰이더, 타일 렌더링, 썸네일
src/io/JPEG 열기, EXIF 읽기·쓰기, 저장·공유, 샘플
src/app/화면 컴포넌트(Header, ContactSheet, Preview, ControlPanel, ThemeSwitcher), 확대 계산

src/tuning/개발 서버 전용 프리셋 튜닝 화면

4.2 처리 흐름

  1. JPEG를 열면 헤더(SOF·EXIF·ICC)를 먼저 읽고, EXIF 회전을 반영해 디코딩한 뒤 긴 변 2048px 미리보기와 512px 썸네일을 만든다.
  2. 고른 프리셋 JSON을 33³ LUT로 굽고, 셰이더가 mix(원본, LUT 결과, 강도)에 비네팅과 입자를 더한다.
  3. 저장할 때는 원본을 다시 디코딩해 2048px 타일로 나눠 그리고, 한 캔버스에 이어 붙여 JPEG로 인코딩한 뒤 고친 EXIF를 끼운다.

4.3 테마 구조

기능 컴포넌트는 하나만 두고, 테마는 data-theme 속성 + CSS 의미 토큰 + 문구 사전(copy.ts) + 장식 slot(ThemeKit)으로만 바꿉니다. 컴포넌트 안에 색상값이나 if (theme === …) 분기를 두지 않습니다.

6. 주요 의사결정과 이유

결정이유
프리셋을 JSON 파라미터로 정의하고 실행할 때 LUT로 굽기셰이더에 프리셋별 분기가 없어지고, 사용자 LUT도 같은 경로로 처리
HSL 조정을 OKLCh 8구간에서색상 이동 시 밝기가 덜 흔들려 튜닝이 안정적
타일 저장을 M2로 앞당김한 번에 그리면 모바일 GPU의 최대 텍스처 크기를 넘을 수 있음
입자를 사진 좌표 기준 값 노이즈로타일 이음매가 생기지 않고, 미리보기·확대·저장에서 같은 자리에 생김
Adobe RGB는 안내만Chromium이 디코딩할 때 sRGB로 자동 변환함을 테스트로 확인
스마트폰 저장 상한 24MP쓰는 사진이 24MP 이하라 실측 대신 결정으로 확정
스마트폰은 저장과 공유를 두 단계로공유 시트는 방금 누른 동작에서만 열려, 긴 렌더링 뒤에는 열리지 않음
사진 우선 배치, 1399px 이하에서 왼쪽 장식 열 숨김일반 창에서 사진이 너무 작다는 피드백
저장 버튼을 추가하지 않고 헤더 고정필름 스트립까지 스크롤해도 저장 버튼이 보임
테마 버튼을 헤더 도구 줄 끝에스마트폰에서 ‘사진 열기’가 아래 저장 줄에 있어 같은 자리를 유지하려고
확대는 Ctrl+휠, 두 번 누르기, 버튼그냥 휠은 페이지 스크롤을 빼앗음
별표는 조절판의 토글 하나로스마트폰 96px 칸에 44px 버튼을 겹치면 잘못 누르기 쉬움
오프라인 글꼴은 쓴 만큼만 보관한글 글꼴 조각 파일이 1,000개 넘고 약 23MB

7. 문제 해결 기록

문제원인해결
세로 사진을 저장하면 조각이 뒤섞임Chromium이 EXIF 회전을 반영한 비트맵을 createImageBitmap으로 자를 때 회전 전 좌표로 자름타일 조각을 2D 캔버스 drawImage로 잘라 옮김, 회전 사진 여러 타일 e2e 추가
비교 슬라이더가 44px 높이에서만 끌림전역 input[type='range'] 규칙이 더 구체적이었음선택자를 input[type='range'].compare-input로 높여 사진 전체를 덮음
모든 칸에 LOADED 표시스크립트 치환이 같은 문자열 여러 곳을 바꿈되돌리고 회귀 검사 추가, 이후 치환은 일치 1개를 확인하도록
스마트폰에서 화면이 옆으로 조금 밀림B 헤더 프레임 카운터, C 마스킹 테이프스마트폰에서 카운터 숨김, .app{overflow-x: clip}
C 구름 장식이 헤더 버튼을 가림배경 장식 위치폴라로이드 위쪽 가장자리로 이동
공유 대기 해제 코드가 lint 규칙 위반effect 안에서 상태 변경저장 당시 값과 지금 값을 비교해 파생 값으로 계산
오프라인에서 앱이 안 열림모듈 스크립트 요청에 Origin 머리글이 붙고 서버가 Vary: Origin을 줘 보관본과 맞지 않음서비스 워커에서 ignoreVary로 찾음
조절판 버튼 추가 후 테마 카드 모양이 어긋남테마 CSS가 카드를 :first-child 순서로 고름:nth-child(n of .control-card)로 바꿔 버튼을 세지 않음
비네팅을 넣은 뒤 타입 검사 오류두 캔버스 종류를 함께 받는 getContext의 반환 타입을 TS가 넓게 잡음WebGL2RenderingContext로 명시
테스트 중 Claude Code가 멈춤e2e를 병렬로 많이 돌려 메모리 부족e2e 동시 실행 수를 2개로 줄여 돌림

8. 보안/성능 고려사항

8.1 개인 정보

  • 사진과 파생물(썸네일, 렌더 결과)은 기기 밖으로 나가지 않습니다. 서버 업로드, 분석 도구, 외부 글꼴·CDN 요청이 없습니다.
  • 서비스 워커는 앱 파일만 보관합니다. 사진은 기기 안의 파일이라 서비스 워커를 거치지 않습니다.
  • 저장소에 넣는 샘플 사진은 스크립트로 EXIF·GPS·XMP·게인 맵을 지웁니다. 앱이 저장하는 결과물은 사용자의 결정에 따라 GPS를 유지합니다.
  • 후지필름 공식 LUT는 luts/private/에만 두고 커밋하지 않습니다. 앱 정보에 비제휴 고지를 둡니다.

8.2 성능

  • 미리보기는 긴 변 2048px 축소본으로 그리고, 썸네일은 사진이나 사용자 LUT가 바뀔 때만 다시 만듭니다.
  • 저장은 2048px 타일로 나눠 GPU 텍스처 한계와 메모리 급증을 피합니다. 24MP 저장 약 0.6초(데스크톱), 61MP 저장 약 2.7~6초(헤드리스 소프트웨어 GPU).
  • 100% 확대는 화면 크기만큼만 잘라 올리고, 맞춤 보기로 돌아가면 원본 비트맵(24MP 약 96MB)을 바로 놓아줍니다.
  • 테마 글꼴은 그 테마를 고를 때 불러옵니다.

  • 색 정확도는 JPEG 인코딩 전 렌더 결과(readPixels)로 비교합니다. 개발 서버에서만 열리는 검사용 창구 window.__filmlook을 씁니다.
  • 기능을 바꿀 때마다 npm run build, npm run test, npm run lint와 e2e 전체를 돌렸습니다.
  • 데스크톱 1440×900과 스마트폰 360·390·430px에서 세 테마의 화면을 직접 확인하고 가로 넘침을 측정했습니다.
  • 새 글자색 조합은 WCAG 대비를 계산해 모두 4.5:1 이상임을 디자인 가이드에 기록했습니다.
  • 배포 빌드에서 서비스 워커 등록과 오프라인 다시 불러오기를 확인했습니다.

10. 배포

  • GitHub Actions(.github/workflows/deploy.yml): main에 올리면 lint → 단위 테스트 → 빌드 → GitHub Pages 배포
  • 주소: https://poguni.github.io/filmlook-studio/ (저장소 Settings → Pages → Source를 GitHub Actions로 켠 뒤 열림)
  • PWA로 홈 화면에 설치할 수 있습니다(매니페스트 이름 ‘색감 사진관’).

11. 알려진 한계

  • JPEG를 다시 가공한 근사치라 실제 후지 필름 시뮬레이션과 결과가 다릅니다.
  • 갤럭시 Ultra HDR 사진은 HDR 정보를 빼고 SDR JPEG로 저장합니다.
  • 스마트폰은 24MP를 넘는 사진을 24MP로 줄여 저장합니다(실기기 측정 전 결정값).
  • 64MP를 넘는 사진(갤럭시 200MP 등)은 따로 다루지 않아 메모리가 부족할 수 있습니다.
  • 저장은 메인 스레드에서 타일 사이에 양보하며 진행해, 저장 중에는 화면 조작이 막힙니다.
  • 오프라인에서는 온라인에서 한 번도 쓰지 않은 테마 글꼴이 기본 글꼴로 보입니다.
  • Safari·Firefox는 필수 지원 대상이 아니고 확인하지 않았습니다. WebGL2가 없으면 안내만 표시합니다.
  • 별표와 비교 위치는 새로고침하면 사라집니다(의도된 동작).

12. 향후 개선 아이디어 / 업데이트 계획

12.1 아직 구현하지 않은 기능 (PRD 요구 사항)

ID기능우선순위메모

C-04밀착 인화 칸에 마우스를 올리거나 길게 누르면 크게 미리 보기P2칸을 누르면 바로 큰 미리보기에 적용되어 효과는 작음

12.2 아직 확인하지 않은 것 (실기기·실사진)

  • 갤럭시 실기기: 스마트폰 저장 상한(24·50·61MP)과 저장 시간 측정, 두 단계 공유 시트, 비교 슬라이더 터치, 두 손가락 확대, 홈 화면 설치와 비행기 모드 실행, A·C 테마 화면
  • 실제 소니 Adobe RGB 사진의 색 변환, 삼성 인터넷에서의 동작
  • 실제 카메라 사진으로 61MP 저장 시간(디코딩이 합성 사진보다 오래 걸릴 수 있음)
  • 성공 기준: 직접 찍은 사진 20장 이상 보정·저장, 열기부터 저장까지 30초 이내
